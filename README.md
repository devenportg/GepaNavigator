# GepaNavigator

Разработка программного продукта для осуществления диспансерного наблюдения больных хроническими гепатитами в соответствии с требованиями клинических рекомендаций, как одного из модулей единой государственной информационной системы здравоохранения (ГИС ЭЗ РТ).

> Гепатит C излечим — но пациент выпадает из наблюдения: **данные в системе есть, а действий по ним нет.** ГепаНавигатор добавляет клинический слой поверх ГИС ЭЗ РТ, который превращает накопленные данные в конкретные действия врача и напоминания пациенту.
>
> **Только демонстрационный MVP, не медицинская система для клинического применения.** Правила клинических рекомендаций упрощены и требуют актуальной проверки профильными специалистами; боевые интеграции и отправка уведомлений не подключены. YandexGPT можно включить отдельно для синтетических данных; реальную медицинскую информацию не загружайте. Демо-пароли и ключи предназначены только для локального тестирования; проект не сертифицирован и не готов к production.
>
> **Технологический выбор ограничен двумя продуктами:** Yandex Cloud как целевая облачная платформа и YandexGPT как единственный AI-инструмент. Размещение приложения в Yandex Cloud не выполняется; опциональная интеграция YandexGPT выключена по умолчанию. Дополнительные AI/BI-сервисы не используем.

## Быстрый старт

```bash
cp .env.example .env && SEED_DEMO=true docker compose up --build   # UI http://localhost:8080 · API http://localhost:8000/docs
```

или локально: `make run-be` (порт 8000, включает демо-seed) + `make run-fe` (порт 5173). Демо-учётки создаются только при явном `SEED_DEMO=true`: `doctor@gepa.local / doctor123` (все роли — в `docs/04_development.md`).

### YandexGPT (необязательная интеграция)

Интеграция выключена по умолчанию. Для локального Docker Compose или `make run-be` задайте в игнорируемом Git файле `.env` `YANDEXGPT_ENABLED=true`, `YANDEXGPT_API_KEY` (ключ сервисного аккаунта) и `YANDEXGPT_FOLDER_ID`; перечень переменных есть в `.env.example`. Для точного URI инстанса из AI Studio, например `gpt://<folder-id>/yandexgpt-4-lite/latest`, задайте `YANDEXGPT_MODEL_URI` с тем же ID папки; если он пуст, используется `gpt://<folder-id>/yandexgpt/<YANDEXGPT_MODEL_VERSION>`. Ключ не добавляйте в Git, frontend или чат. После изменения конфигурации перезапустите backend.

Запрос в Yandex Cloud выполняется только по действию врача. В него входят введённые жалобы и инструкция, код диагноза и ближайшее событие действующего плана; поля ФИО и регистрационных идентификаторов в запрос не включаются. В свободном тексте всё равно нельзя указывать ФИО, контакты, номера документов или реальные медицинские сведения — используйте только синтетические данные. Модель создаёт редактируемый черновик, не меняет клинический план и не подписывает приём. Если сервис включён, но не настроен или недоступен, операция вернёт ошибку, а не заменит ответ локальным шаблоном.

## Структура

```
backend/    FastAPI: регистр, мотор правил КР, рабочее место, Care Mgmt, уведомления, интеграции, аналитика, аудит
frontend/   React+TS: одно окно врача (зоны green/yellow/red/purple-УВО), карточка пациента, задачи обзвона, аналитика
e2e/        Сквозной сценарий ТЗ §3.3.4 через реальный HTTP-стек
docs/       Этап 1 (бизнес-аналитика) + этап 2 (разработка)
```

## Тесты

```bash
cd backend && python -m pytest tests -q   # BE: unit правил КР + API
cd frontend && npm test && npm run build  # FE: unit/component + сборка
python -m pytest e2e -q                   # E2E: полный клинический путь
```
