# GepaNavigator

Разработка программного продукта для осуществления диспансерного наблюдения больных хроническими гепатитами в соответствии с требованиями клинических рекомендаций, как одного из модулей единой государственной информационной системы здравоохранения (ГИС ЭЗ РТ).

> Гепатит C излечим — но пациент выпадает из наблюдения: **данные в системе есть, а действий по ним нет.** ГепаНавигатор добавляет клинический слой поверх ГИС ЭЗ РТ, который превращает накопленные данные в конкретные действия врача и напоминания пациенту.

## Этапы

| Этап | Статус | Содержание |
|---|---|---|
| 1. Бизнес-аналитика | ✅ | [`docs/`](docs/README.md): предметная область, проблема, функционал и архитектура |
| 2. Разработка MVP (до 27.11) | ✅ | **2.1** Backend + тесты + инфраструктура · **2.2** Frontend + тесты · **2.3** Проверка e2e — см. [`docs/04_development.md`](docs/04_development.md) |
| 3. Пилот в 1–2 МО РТ | ⏳ | Опытная эксплуатация, доработка по обратной связи врачей |

## Быстрый старт

```bash
cp .env.example .env && docker compose up --build   # UI http://localhost:8080 · API http://localhost:8000/docs
```

или локально: `make run-be` (порт 8000) + `make run-fe` (порт 5173). Демо-учётки: `doctor@gepa.local / doctor123` (все роли — в `docs/04_development.md`).

## Структура

```
backend/    FastAPI: регистр, мотор правил КР, рабочее место, Care Mgmt, уведомления, интеграции, аналитика, аудит
frontend/   React+TS: одно окно врача (зоны green/yellow/red/purple-УВО), карточка пациента, задачи обзвона, аналитика
e2e/        Сквозной сценарий ТЗ §3.3.4 через реальный HTTP-стек
docs/       Этап 1 (бизнес-аналитика) + этап 2 (разработка)
```

## Тесты

```bash
cd backend && python -m pytest tests -q   # BE: unit правил КР + API
cd frontend && npm test && npm run build  # FE: unit/component + сборка
python -m pytest e2e -q                   # E2E: полный клинический путь
```
