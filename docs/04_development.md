# Этап 2 · Разработка MVP (2.1 BE · 2.2 FE · 2.3 e2e)

Срок по плану: **до 27.11**. Реализован MVP по приоритету «Этап 2» из
[`03_functional_requirements.md`](./03_functional_requirements.md): регистр пациентов,
клинический слой по КР (базовые правила ВГС/ВГВ), рабочее место врача, базовые напоминания.

## Что реализовано по функциональным блокам

| Блок из ТЗ | Реализация | Где |
|---|---|---|
| 1. Автоматический регистр | Пациенты B18.*, дедупликация по СНИЛС / ФИО+ДР (409 при дубле), статусы наблюдения, триггеры постановки: диагноз B18.*, ПЦР+, HBsAg+, запись ФРВГ — через webhook интеграций | `backend/app/main.py`, `services.py` |
| 2. Клинический слой (мотор правил КР) | Индивидуальный план: приём 1 р/6 мес, анализы 2 р/год, УЗИ+эластометрия 1 р/год, при циррозе — скрининг ГЦР каждые 6 мес, контроль **УВО-12 ровно +12 недель** после ПВТ, окно ±14 дней, пересчёт просрочек, объяснение каждого назначения (`rule_ref`) | `backend/app/rules.py` (чистые функции, unit-тесты) |
| 3. Рабочее место врача | Список пациентов с цветовой разметкой green/yellow/**red**/**purple (УВО)**, карточка пациента, чек-лист плана, проведение приёма, черновик заключения AI-ассистента (mock-фасад YandexGPT за тем же интерфейсом), назначение/завершение ПВТ | `frontend/src/App.tsx`, API `/worklist`, `/encounters` |
| 4. Care Management | Эскалация красной зоны в задачи обзвона (приоритет ↑ при просрочке >30 дней), журнал исходов обзвона (придёт/отказался/не отвечает/недоступен) | `/api/care/tasks`, дневной job |
| 5. Коммуникации с пациентом | Напоминания за 7/1 день до визита, за 10 дней до анализов, об УВО-12; журнал уведомлений; **без согласия — SKIPPED_NO_CONSENT** (152-ФЗ) | `services.generate_reminders`, `/api/notifications` |
| 6. Интеграции | Webhook событий ГИС ЭЗ РТ / ФРВГ (`X-Integration-Key`), FHIR-подобный payload Condition/Observation; не-триггерные события игнорируются | `/api/integrations/gis/events` |
| 7. Аналитика | Охват, приверженность (выполнено/(выполнено+просрочено)), доля УВО-12, зоны, нагрузка по врачам, разрезы по нозологиям | `/api/analytics/overview`, экран «Аналитика» |
| 8. Администрирование и ИБ | JWT, RBAC (doctor/head/nurse/analyst/admin), аудит всех значимых действий (просмотр — только head/admin) | `security.py`, `/api/audit` |
| Scheduler | Дневной job: пересчёт просрочек → напоминания → эскалация | `POST /api/jobs/run-daily` |

## Архитектура и стек

Модульный монолит (решение ТЗ §3.3.3 «на первом этапе»), выделение микросервисов — после пилота.

- **Backend:** Python 3.11+ / FastAPI / SQLAlchemy / PostgreSQL (в dev — SQLite), JWT (PBKDF2-хеш паролей)
- **Frontend:** TypeScript / React 18 / Vite, одно окно врача, встраивание в ГИС ЭЗ РТ — через единый origin (`/api` проксируется)
- **Инфраструктура:** Docker Compose (PostgreSQL + backend + frontend/nginx), GitHub Actions CI, Makefile
- **AI-фасады:** YandexGPT/SpeechKit/Vision в MVP — детерминированные mock-реализации за теми же интерфейсами (`rules.draft_conclusion`), подключение боевых API — этап расширения, без изменения API-контрактов.

## Как запустить

```bash
# Вариант А — Docker (полный стек с PostgreSQL)
cp .env.example .env && docker compose up --build   # UI: http://localhost:8080, API: http://localhost:8000/docs

# Вариант Б — локально для разработки
cd backend && pip install -r requirements-dev.txt && uvicorn app.main:app --port 8000
cd frontend && npm install && npm run dev            # UI: http://localhost:5173
```

Демо-данные (8 пациентов во всех зонах, включая контроль УВО-12) создаются при первом старте (`SEED_DEMO=true`).

**Демо-учётки:** `doctor@gepa.local/doctor123` · `head@gepa.local/head12345` ·
`nurse@gepa.local/nurse1234` · `analyst@gepa.local/analyst123` · `admin@gepa.local/admin12345`

## Тестирование (2.1 / 2.2 / 2.3)

| Уровень | Команда | Покрытие |
|---|---|---|
| BE unit | `cd backend && python -m pytest tests -q` | Правила КР: план при циррозе, УВО-12 = +12 нед, окно просрочки, приоритет зон purple>red, расписание напоминаний |
| BE API | (тот же suite) | Auth/RBAC, дедупликация регистра, webhook ГИС, приём→след. визит, терапия→УВО-12, согласие 152-ФЗ, эскалация, аудит |
| FE unit/component | `cd frontend && npm test` | Утилиты дат/зон, ZoneBadge (4 цвета ТЗ), строка пациента, клик-открытие карточки |
| FE build | `cd frontend && npm run build` | TypeScript strict + production build |
| **E2E (2.3)** | `python -m pytest e2e -q` | Поднимает реальный стек (uvicorn + собранный фронт) и проходит ключевой сценарий ТЗ §3.3.4: событие ГИС B18.2 → регистр и план → рабочее место → приём с черновиком → завершение ПВТ → УВО-12 → УВО достигнут в аналитике; отдельно: дневной job → задача обзвона → исход WILL_COME → аудит и RBAC |

CI (`.github/workflows/ci.yml`): три job — backend, frontend, e2e — на каждый push/PR.

## Что сознательно вне MVP (следующие этапы ТЗ)

Боевые интеграции (ГИС ЭЗ РТ, ЕГИСЗ/РЭМД, ФРВГ, ЛИС по FHIR, СМЭВ/Госуслуги), реальные
YandexGPT/SpeechKit/Vision, DataLens/ClickHouse, Keycloak SSO, голосовой робот,
УВО-24-ветка снятия с учёта и посттерапевтическое наблюдение 1–2 года, аттестация ФСТЭК.
Точки расширения отмечены в коде (AI-фасад, webhook-адаптер, аналитический API).
