# Этап 2 · Разработка MVP (2.1 BE · 2.2 FE · 2.3 e2e)

Срок по плану: **до 27.11**. Реализован MVP по приоритету «Этап 2» из
[`03_functional_requirements.md`](./03_functional_requirements.md): регистр пациентов,
клинический слой по КР (базовые правила ВГС/ВГВ), рабочее место врача, базовые напоминания.

> **Ограничения демонстрации:** это не медицинская система для клинического применения и не production-ready продукт. Клинические правила упрощены и нуждаются в актуальной проверке специалистами; боевые интеграции и отправка уведомлений не подключены. Черновик по умолчанию формируется локальным шаблоном; опциональный серверный вызов YandexGPT выключен по умолчанию и предназначен только для синтетических данных. Не используйте реальные персональные или медицинские данные. Демо-пароли и ключи нельзя использовать в развёртывании.

## Архитектура и стек

Модульный монолит (решение ТЗ §3.3.3 «на первом этапе»), выделение микросервисов — после пилота.

- **Backend:** Python 3.11+ / FastAPI / SQLAlchemy / PostgreSQL (в dev — SQLite), JWT (PBKDF2-хеш паролей)
- **Frontend:** TypeScript / React 18 / Vite, одно окно врача, встраивание в ГИС ЭЗ РТ — через единый origin (`/api` проксируется)
- **Инфраструктура:** локальный Docker Compose (PostgreSQL + backend + frontend/nginx); целевая облачная платформа — только Yandex Cloud.
- **AI:** единственный AI-инструмент — YandexGPT через Yandex Cloud AI Studio Chat Completions API. Интеграция настраивается серверными переменными `YANDEXGPT_*` и выключена по умолчанию; при заданном `YANDEXGPT_MODEL_URI` используется точный URI инстанса AI Studio, иначе URI строится из ID папки и `YANDEXGPT_MODEL_VERSION`. Без интеграции используется локальный шаблон `rules.draft_conclusion`. Облачный вызов выполняется только по явному действию врача, использует синтетический контекст и русскоязычный системный промпт; врач проверяет и редактирует черновик, который не меняет клинический план и не подписывает приём.

## Как запустить

```bash
# Вариант А — Docker (полный стек с PostgreSQL)
cp .env.example .env && SEED_DEMO=true docker compose up --build   # UI: http://localhost:8080, API: http://localhost:8000/docs

# Вариант Б — локально для разработки (в двух терминалах из корня репозитория)
(cd backend && pip install -r requirements-dev.txt && SEED_DEMO=true uvicorn app.main:app --port 8000 --env-file ../.env)
(cd frontend && npm ci && npm run dev)                 # UI: http://localhost:5173
```

Демо-данные (8 пациентов во всех зонах, включая контроль УВО-12) создаются при первом старте (`SEED_DEMO=true`).

**Демо-учётки:** `doctor@gepa.local/doctor123` · `head@gepa.local/head12345` ·
`nurse@gepa.local/nurse1234` · `analyst@gepa.local/analyst123` · `admin@gepa.local/admin12345`

## Что сознательно вне MVP (следующие этапы ТЗ)

Боевые интеграции (ГИС ЭЗ РТ, ЕГИСЗ/РЭМД, ФРВГ, ЛИС по FHIR, СМЭВ/Госуслуги), размещение в Yandex Cloud и использование YandexGPT с реальными данными не реализованы. Опциональная YandexGPT-интеграция предназначена только для демонстрации на синтетических данных; другие AI-сервисы не используются. Также вне MVP — УВО-24-ветка снятия с учёта, посттерапевтическое наблюдение 1–2 года и аттестация ФСТЭК.
