# 1.2 Определение проблемы, которую решает проект

## Проблема верхнего уровня

> **Пациенты с хроническими гепатитами систематически «выпадают» из диспансерного наблюдения, несмотря на то что все необходимые данные о них уже существуют в информационных системах.**

Гепатит C сегодня излечим современными препаратами прямого противовирусного действия (ПППД), которые обеспечивают устойчивый вирусологический ответ у 95–98 % пациентов. Но излечение невозможно без того, чтобы пациент дошёл до врача, прошёл обследование, получил назначение и закончил терапию под контролем.

---

## Коренные причины проблемы

На основе интервью с 8 врачами-инфекционистами и 3 организаторами здравоохранения РТ выделяются следующие причины разрыва между «данными» и «действиями»:

### 1. Разрозненность данных (фрагментация ИТ-ландшафта)
Врач ведёт пациента, работая одновременно в **четырёх и более системах**:
- Региональная МИС (ГИС ЭЗ РТ / qMS / БАРС)
- Федеральный регистр вирусных гепатитов (ФРВГ)
- ЕГИСЗ (в части ОМС, льготных рецептов)
- Лабораторные системы (результаты анализов)
- **Плюс собственные Excel-таблицы** для составления списка пациентов на приём

**Следствие:** на формирование списка тех, кто должен прийти в текущем месяце, врач тратит часы рабочего времени; риск человеческой ошибки высок.

### 2. Отсутствие клинической логики поверх данных
Существующие МИС хранят факты (диагнозы, анализы, даты визитов), но не содержат **клинического слоя** — набора правил по клиническим рекомендациям, который бы автоматически:
- определял, какие обследования должны быть выполнены в текущем окне;
- сигнализировал о просроченном визите или анализе;
- формировал индивидуальный план наблюдения с датами;
- выявлял пациентов с риском выпадения.

**Следствие:** о пациенте, пропустившем визит, врач узнаёт не от системы, а когда пациент возвращается уже с осложнением (цирроз, ГЦР).

### 3. Отсутствие двусторонней коммуникации с пациентом
В системах МИС нет механизма проактивного напоминания пациенту:
- о предстоящем визите;
- о необходимости сдать анализы до приёма;
- о контроле УВО после терапии.

**Следствие:** пациент не знает своего маршрута и забывает о явке, приверженность наблюдению низкая.

### 4. Нет операционной аналитики для управления
У Минздрава и главврачей нет в реальном времени панели, показывающей:
- охват диспансерным наблюдением в разрезе МО/района;
- приверженность (долю явившихся);
- долю достигших УВО (индикатор качества терапии);
- нагрузку на каждого инфекциониста.

**Следствие:** управленческие решения принимаются на основе устаревших сводок, невозможно оперативно влиять на показатели региона.

### 5. Большая доля неструктурированных данных
Архивные выписки, бумажные анализы, результаты из внешних лабораторий попадают в систему в виде сканов/фотографий. Врач тратит время на ручной перенос данных, часть информации теряется.

**Следствие:** база данных о пациентах неполна, автоматические правила работают на ограниченном множестве данных.

## Ценностное предложение по стейкхолдерам

| Стейкхолдер | Проблема («боль») | Решение от ГепаНавигатора |
|---|---|---|
| **Врач-инфекционист** | Списки вручную в Excel, забытые пациенты, поиск по 4 системам | «Система сама показывает, кто должен прийти и что назначить»: готовый список пациентов на месяц, чек-лист обследований по КР, черновик заключения от YandexGPT |
| **Пациент** | Не знает маршрута, забывает о визитах, повторяющиеся вопросы | «Меня не забыли»: напоминания (СМС/push/Госуслуги), понятный маршрут обследований, контроль УВО |
| **Главврач / заведующий** | Нет картины по отделению в реальном времени | Дашборд нагрузки, охвата, приверженности по своему МО |
| **Минздрав РТ** | Отчёты запаздывают, нет сквозной видимости по региону | Региональный дашборд: охват, УВО, вклад в элиминацию гепатита C |
| **Оператор ГИС ЭЗ РТ** | Отдельные решения не встраиваются в контур | Нативный модуль ГИС ЭЗ РТ, соответствующий 152-ФЗ, аттестация ФСТЭК, росПО |

## Формулировка проблемы в одном абзаце

В Республике Татарстан, несмотря на наличие работающей региональной ГИС ЭЗ РТ с десятками миллионов медицинских документов и федерального регистра гепатитов, пациенты с хроническими гепатитами систематически выпадают из диспансерного наблюдения. Причина — отсутствие клинического слоя, который бы автоматически применил правила клинических рекомендаций к накопленным данным и превратил их в конкретные действия: список пациентов на приём, план обследований, напоминания пациенту и тревоги при пропуске визита. Врач вручную собирает информацию из нескольких систем и Excel-таблиц, пациент не получает своевременных напоминаний, а Минздрав не видит реальной картины охвата и результатов терапии. Результат — несвоевременно начатая терапия, развившиеся осложнения (цирроз, ГЦР), лишние затраты ОМС и невыполнение показателей национального проекта по элиминации вирусного гепатита C.

## Цель проекта

Автоматизировать и повысить полноту и своевременность диспансерного наблюдения пациентов с хроническими гепатитами в Республике Татарстан на основе клинических рекомендаций Минздрава РФ путём внедрения нативного цифрового модуля «ГепаНавигатор» в контур ГИС ЭЗ РТ.

### Целевые эффекты первого года внедрения:
1. **−40 %** пропущенных плановых визитов.
2. **≥ 90 %** пациентов с диагнозом B18.* охвачены структурированным диспансерным наблюдением.
3. **100 %** данных о наблюдении структурированы и передаются в ЕГИСЗ / ФРВГ.
4. Время врача на формирование плана приёма сокращено с часов до минут.
5. Минздрав получает онлайн-доступ к показателям региона.
